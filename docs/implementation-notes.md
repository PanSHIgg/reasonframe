# 首版实现与已发现的问题

服务将 agent 编辑能力、确定性编译和质量门分开。作者只改源文件；审核和渲染由服务调用。当前没有发布到视频平台、网页工作台或多人协作层。

## 从原 demo 迁移时发现的两类问题

第一类是检查器自身的边界错误。早期浏览器检查硬编码了场景底部安全线，把位于场景内部的注释误判为越界。现在依据真实场景底部与字幕区域的边界判定。检查器需要和画布结构一致，不能用随意选取的像素线判断所有元素。

第二类是过稀的采样遗漏实际缺陷。原 demo 的稀疏检查将坐标轴 z 标签超出模型区域约 6 px 记作瞬时信息；加入过渡采样后确认其持续存在，成为阻断错误。样例将 coordinates/vectors 的模型视窗下移，修复实际越界后重新检查，没有添加忽略规则。

同一视频必须同时检查“内容采样点”和“动画过渡采样点”。对象 cue 检查覆盖每个词句提示，HyperFrames 对进入、退出、公式变化进行额外采样；二者发现的问题不同。

第三类是编码比较的格式不一致。直接在全分辨率 RGB 通道做 SSIM，会放大 H.264 4:2:0 色度抽样对黑底彩色细线的正常影响。现在两张图都统一为 BT.709、有限范围 YUV420p 后比较，保留 0.97 阈值。实际球面帧约为 0.985，错场景对照约为 0.902；回归测试同时覆盖正常编码图和明显变化的图，避免仅降低阈值消除错误。

## 质量边界

数值检查使用受限表达式和画面的同一份 model；立体几何样例还用垂直平分方程独立恢复球心。相对与绝对容差分开；默认绝对容差为 0，避免把 1.6e-19 等物理量判为零。对浮点几何的零值，作者须显式填写适合单位的绝对容差。

独立审核隔离作者上下文，并没有引入第二家模型。它会独立解题再读稿，但不能承诺不受共同偏差影响。后续值得扩展的是各学科可重复的数学/物理/化学验证器、独立 ASR 复核、题目基准集与多模型交叉验证。

作者与审核的会话、事件、每项检查的报告、渲染和解码日志都保留在任务目录。固定样例用 SDK fixture 跑工具流程；真实模型及 TTS 的行为必须在配置实际服务后另行验证。

## 运行范围

单进程、文件持久化队列；任务并发和渲染 worker 数可配置。锁文件防止两个进程同时占用状态目录。崩溃时正在执行的任务标为 interrupted，等待显式重试；不会在服务重启时自动补发付费模型或 TTS 请求。

Pi 没有任意 shell 和任意文件访问；产物使用清单下载，浏览器资源本地化，并限制外部资源请求。这些限制不等同于多租户不可信代码沙箱。若对公网提供第三方题目生成服务，应在独立容器/工作节点中运行渲染，并另做身份、配额、资源调度和持久化存储。

已经通过成片校验但尚未发布的 pending.mp4 可以在重试中复用。复用前同时检查视频字节、源文件、时间线、所有编译资源及校验器实现的摘要；任一变化都会重新渲染或校验，失败的视频不会成为缓存命中。
